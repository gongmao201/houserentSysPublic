## 2. 报修状态机

### 2.1 流转矩阵（6×6 已单测穷举）

| 当前 \ 目标 | ACCEPTED | ON_SITE | COMPLETED | ACCEPTED_BY_TENANT | CANCELLED |
|---|---|---|---|---|---|
| CREATED | ✅ | ❌ | ❌ | ❌ | ✅ |
| ACCEPTED | ❌ | ✅ | ❌ | ❌ | ✅ |
| ON_SITE | ❌ | ❌ | ✅ | ❌ | ✅ |
| COMPLETED | ❌ | ❌ | ❌ | ✅ | ✅ |
| ACCEPTED_BY_TENANT | ❌ | ❌ | ❌ | ❌ | ❌（终态） |
| CANCELLED | ❌ | ❌ | ❌ | ❌ | ❌（终态） |

- 动作映射：`accept→ACCEPTED`、`arrive→ON_SITE`、`complete→COMPLETED`、`confirm→ACCEPTED_BY_TENANT`、`cancel→CANCELLED`。
- 同状态重复操作返回 409「工单已是 X，重复操作不再受理」。
- 白名单外返回 409「状态流转非法：A → B，允许：…」；终态返回「该状态为终态，不可再流转」。
- 权限：`accept/arrive/complete` 房东或管理员；`confirm` 租客；`cancel` 租客/房东/管理员（FR-REPAIR-04）。
- 每次成功流转写 `repair_log`，`version + 1`，响应与详情均回传 `allowedNext`。

### 2.2 幂等规则

| 场景 | 行为 |
|---|---|
| 首次提交 | 正常创建，落 `idem_key` |
| 同 key + 同租客 + ≤24h | 返回首次 `repairId`，不产生新工单 |
| 同 key + 不同租客 | 409「已被其他用户使用」，防止跨人读取工单 |
| 同 key + 首次提交 >24h | 409「已超过 24 小时有效期，请更换后重试」 |
| 并发同 key（唯一键冲突） | 捕获 `DuplicateKeyException` 后回查，按上述同一规则处理 |
| key 为空/空白 | 不启用幂等；超 64 字符 400 |

## 6. 已知限制与待确认

1. **webp 不压缩**：JDK 14 无 webp 解码器，原图落盘；若前端主用 webp，需要加 `webp-imageio` 依赖或前端先转 jpg。
2. **EXIF 方向未处理**：手机竖拍照片若依赖 EXIF Orientation，压缩后可能显示为横向，需前端 `image-orientation` 或后续接 `metadata-extractor`。
3. **透明 PNG 转 JPEG**：透明区域铺白底，带透明通道的房源 logo 会变白底；如需保留透明，需单独走 PNG 分支。
4. **409 仍为 HTTP 200 + body 业务码**：与 `docs/13` 的“409”表述存在口径差异，属 v2 统一异常处理策略，待需求方确认是否改真实 HTTP 状态码。
5. **COMPLETED→CANCELLED 可取消**：按 `docs/14`「任意非终态可取消」实现；若产品只允许完工前取消，需要收窄白名单。
6. **`url` 仍为 `/images`**：契约写 `/uploads`，存量静态映射是 `/images`，T-12 未收口。

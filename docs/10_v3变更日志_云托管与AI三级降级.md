## 决策一：后端迁移到微信云托管（D17）

### 为什么改

v2.3 的部署方案是"4C8G 自维护云服务器（MySQL+Redis+API+Nginx+监控）"，月费 150-250 元，需要自管 HTTPS 证书、Nginx 配置、带宽、备案域名。

**微信云托管（CloudBase Run）一次性解决三个问题**：
1. **默认域名已 ICP 备案**——小程序前端 request 合法域名直接合法，不需要自己买域名、做备案、配证书。
2. **MySQL/Redis 内置**——不用自己 docker-compose 维护数据库。
3. **免运维 Nginx/HTTPS/负载均衡**——云托管自动处理。

### 新部署架构

```
[小程序前端]
    │  HTTPS（云托管默认域名，已备案）
    ▼
[微信云托管 CloudBase Run]
    ├─ Spring Boot API 实例（2C2G 起步，自动伸缩）
    ├─ 内置 MySQL 8.0
    ├─ 内置 Redis 7
    ├─ 文件存储（COS 挂载，替代本地 /uploads）
    │
    │  服务器到服务器（不走小程序域名校验）
    ▼
[花生壳 vicp.fun 穿透]
    │
    ▼
[本机 i5-13500K + Ollama qwen2.5:3b]（仅 AI 文案生成）
    │
    │  第 2 级降级（公网 HTTPS）
    ▼
[DeepSeek API]（可靠兜底）
```

### 关键认知

| 问题 | 答案 |
|---|---|
| 云托管域名需要备案吗？ | **不需要**——CloudBase Run 分配的默认域名已自带 ICP 备案 |
| 花生壳 vicp.fun 需要备案吗？ | **不需要**——这条链路是"云托管服务器→花生壳→本机"的服务器到服务器调用，不经过小程序 request 合法域名校验 |
| 花生壳免费版限制？ | 1 Mbps 带宽、1 GB/月流量、5 并发。课程演示够用，超时设 3s |
| 本机 Ollama 还需要吗？ | **需要**——演示"本地部署 Qwen"的能力仍然成立，通过花生壳暴露给云托管调用 |
| MySQL/Redis 用什么？ | 云托管内置，不用自己装 |

## 决策二：AI 三级自动降级（D18）

### 为什么改

v2.3 是"rule（线上）vs llm（演示机）"双形态开关，需要手动切。
v3 改为**运行时自动三级降级**，不需要人工干预。

### 三级链路

```
用户请求
   │
   ▼
[第 1 级] 云托管 → 花生壳 → 本机 Ollama (qwen2.5:3b)
   │  超时 3s / 连接失败 / HTTP 5xx
   ▼
[第 2 级] 云托管 → DeepSeek API (OpenAI 兼容)
   │  超时 8s / 余额不足 / HTTP 5xx
   ▼
[第 3 级] 纯规则匹配（ai.mode=rule，零外部依赖）
   │
   ▼
返回 HTTP 200 + 结构化结果 + 推荐理由
```

### 配置项

```yaml
ai:
  mode: auto              # auto（默认）| local | deepseek | rule
  local:
    endpoint: https://xxx.vicp.fun
    timeout-ms: 3000
    model: qwen2.5:3b-instruct-q4
  deepseek:
    endpoint: https://api.deepseek.com/v1/chat/completions
    api-key: ${DEEPSEEK_API_KEY}
    timeout-ms: 8000
    model: deepseek-chat
  rule:
    enabled: true
```

### 成本

| 级别 | 成本 | 可靠性 |
|---|---|---|
| 第 1 级 本机 Ollama | 0（电费忽略） | 受家庭网络影响 |
| 第 2 级 DeepSeek | 约 6 元/百万 tokens，课程演示几乎为 0 | 高（腾讯云出口） |
| 第 3 级 规则匹配 | 0 | 最高（零外部依赖） |

### 验收标准

- 停掉花生壳，接口自动走 DeepSeek，仍返回 200。
- 停掉 DeepSeek（清空 API Key），接口自动走规则匹配，仍返回 200。
- 三级全挂，仍返回规则结果 + 模板文案，**绝不 500**。

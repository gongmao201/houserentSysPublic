# 07・评审提示词（供其他 Agent / 同事评审本方案使用）

> 用法：把本文件全文粘贴给任意一个有架构 / 产品 / 前端 / 测试能力的 Agent，并指定其角色进行评审。



***

## 通用评审角色（请你以以下身份之一进行评审）

请选择并进入角色：



* **A. 资深全栈架构师**（评审技术选型、扩展性、风险）

* **B. 资深产品经理**（评审需求完整性、用户体验、商业价值）

* **C. 资深前端架构师**（评审 Vue3 重写、小程序、UI 方案）

* **D. 资深测试 / QA 负责人**（评审测试策略、覆盖度、上线风险）

* **E. 运维 / SRE 工程师**（评审部署、性能、成本、可观测性）



***

## 待评审材料（请基于以下事实评审）

项目背景：



* 现有开源版房屋租赁系统，技术栈为 Spring Boot 老版本 + JDK1.8 + MyBatis + MySQL5.7；Web 端 Vue 2.5 + Element UI + Webpack 3；小程序为原生微信小程序。

* 现有功能：用户 / 房东 / 管理员三角色，房屋搜索、收藏、约看、租房申请、消息。

* 5 人团队：项目经理 1、后端 1、Web 前端 1、小程序 1、文档测试 1。

* 周期 12 周（2026-11-03 \~ 2027-01-23）。

老板提出的 5 条需求：



1. 加 AI：Ollama 本地部署 Qwen2.5，做智能选房；用 Redis + RAG 向量知识库提升行业适配度；最小代价。

2. 双向评分体系：对标 "小美评审团"，官方评审 + 用户评审并存，帮房东筛租客、租客筛房东。

3. UI 美化：Web 和小程序当前简陋空洞，需重做。

4. 加功能：报修、缴费。

5. 性能优化：老旧配置升级。

本方案的核心决策：



* 后端升级到 JDK17 + Spring Boot 3.2；MySQL 升 8.0；新增 Redis 7（同时承担缓存与向量存储）。

* Web 重写为 Vue 3.4 + Vite + TypeScript + Element Plus。

* 小程序保留原生框架，只重做 UI 与新增页面。

* AI 用 qwen2.5:7b-instruct-q4 + nomic-embed-text，本地 CPU 部署（i5-13500K 级别）。

* 评分规则：房源分 = 官方 0.4 + 用户 0.6；房东分 = 官方 0.3 + 用户 0.7；仅租约结束后 30 天内可评。

* 缴费一期只做账单 + 标记已缴，微信支付二期接。

* 分三阶段：P1 基础现代化（W1-W4）、P2 新特性（W5-W9）、P3 打磨上线（W10-W12）。

* 不留情面，像 code review 一样直接指出问题。

## 3. 设计约定

### 3.1 命名

| 对象 | 规则 | 示例 |
|---|---|---|
| 表 | 小写下划线；存量保留 `hrent_` / `sys_` 前缀；新表按域起名 | `repair_order`、`rating_summary` |
| 列 | 小写下划线 | `actual_end_date`、`amount_fen` |
| 主键 | `id`；复合主键按业务键 | `rating_summary(target_type,target_id)` |
| 唯一键 | `uk_<语义>` | `uk_reviewer_target` |
| 普通索引 | `idx_<语义>` | `idx_tenant_status` |
| CHECK | `ck_<表简写>_<语义>` | `ck_repair_status` |
| 逻辑外键 | 不建物理 FK，列名与父表主键同名 | `house_id`、`lease_id` |

### 3.2 主键与 ID

- 统一 `VARCHAR(32)`，32 位无横线 UUID；不用自增数字，避免 JS 精度丢失。
- 存量业务 ID 有前缀习惯：房源 `HR+时间戳`，种子 `SEEDH/SEEDG/SEEDR`。
- 两张表例外：`rating_summary` 用 `(target_type,target_id)` 复合主键；`house_embedding` 用 `house_id` 做 PK。
- Java 侧 `BaseEntity.preInsert()` 生成 UUID；继承它的实体必须保证 `currentUser` 非空，否则 NPE（见 G-13）。

### 3.3 字符集与引擎

- 全库 `utf8mb4` / `utf8mb4_general_ci`；25 张表实测一致。
- 全部 InnoDB。
- JDBC 连接串 `serverTimezone=GMT%2B8`，与 `Asia/Shanghai` 等价；容器/会话时区需保持一致。

### 3.4 统一审计列组（只定义一次）

存量 13 张表统一带以下 6 列；后文逐表字段表用「审计列组」一行引用，不重复展开。

| 列 | 类型 | 空 | 默认 | 说明 |
|---|---|---|---|---|
| `create_by` | `varchar(32)` | 是 | NULL | 创建人 `sys_user.id` |
| `create_time` | `datetime` | 是 | NULL | 创建时间 |
| `update_by` | `varchar(32)` | 是 | NULL | 修改人 `sys_user.id` |
| `update_time` | `datetime` | 是 | NULL | 修改时间 |
| `remake` | `varchar(500)` | 是 | NULL | 备注（存量拼写，不改为 remark） |
| `del_flag` | `int` | 否 | 0 | 0 正常 / 1 删除 |

Java 映射：`create_by → createBy.id`、`create_time → createDate`、`update_by → updateBy.id`、`update_time → updateDate`、`del_flag → delFlag`。

**新表不强制继承这 6 列。** 实测 12 张新表中 `create_by`/`update_by` 命中 0，只有 `review`、`repair_order` 有 `del_flag`；这是设计选择，不是遗漏（见 G-04、G-08）。

### 3.5 逻辑删除

| 表类 | 策略 |
|---|---|
| 存量 13 表 | `del_flag=1` 逻辑删除；查询默认 `del_flag=0` |
| `review`、`repair_order` | 有 `del_flag`，逻辑删除 |
| 其余 10 张新表 | 无 `del_flag`；日志/明细/汇总表只追加或物理删，不做软删 |

理由：日志表软删会让时间线断裂；明细表软删会让金额对账复杂；汇总表可重算，不需要软删。

### 3.6 金额

| 场景 | 类型 | 规则 |
|---|---|---|
| 存量 `money` / `deposit` | `double`（元） | **只读保留**，不再写入新值 |
| 新增 `money_fen` / `deposit_fen` / `amount_fen` / `paid_fen` | `bigint`（分） | 新写入一律用分 |
| 接口层 | 整数分 | 前端 `(fen/100).toFixed(2)` |
| 换算 | `ROUND(x*100)` | 只允许在迁移脚本与 `MoneyUtils` 中做 |

对账口径：`SUM(money) = SUM(money_fen)/100`；抽样 100 行 `ABS(ROUND(money*100)-money_fen)=0`。

### 3.7 时间

| 类型 | 用途 | 示例 |
|---|---|---|
| `datetime` | 事件发生时间 | `create_time`、`pay_time`、`accepted_at` |
| `date` | 业务日期 | `start_date`、`end_date`、`actual_end_date` |
| `varchar(50)` | 存量手工录入时间，保留 | `hrent_house_renting.start_time/end_time`、`hrent_apply_view.view_time` |

- 新字段不再用 `varchar` 存日期。
- 存量 `start_time/end_time` 与新 `start_date/end_date` 双写；迁移时用 `STR_TO_DATE` 三种格式兜底，失败行必须进日志表人工处理。
- 时区三处对齐：JDBC `serverTimezone`、MySQL `time_zone`、容器 `TZ`。

## 9. 安全与隐私

| 项 | 规则 |
|---|---|
| 敏感字段 | `password`、`mobile`、`openid`、`idem_key` 日志脱敏（`138****0001`） |
| 越权 | 每个接口校验 `owner_id`；房东只看自己房源/工单/账单；租客只看自己租约 |
| 金额 | 接口层只传分；禁止 `double` 参与计算 |
| 上传 | 仅 jpg/png/webp，≤5MB；UUID 重命名；禁原始文件名落盘 |
| 注入 | 禁 `${}` 拼接；`LIKE` 用 `CONCAT('%',#{q},'%')` |
| 合规 | 一期不做租客评分；评价可申诉；隐私政策 + 用户协议 + 收集清单 |
| 备份 | 每日全量 + binlog；RPO ≤1h，RTO ≤4h；每周异地一份 |

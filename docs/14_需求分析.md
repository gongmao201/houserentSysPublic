### 2.3 对需求的影响【决策】

- 小程序 UI 需求按 **iView Weapp** 写，不按 Vant 写；否则改造成本会算错一倍。
- 所有本地地址、接口示例统一用 `http://localhost:8888/hrent`，不写 8080。
- 分页需求写「返回 `pageNo/pageSize/count/list`」，但**验收时以实际是否分页为准**；当前是假分页，列入缺口 G-12，不在一期修。
- 新模块（评分/报修/账单/AI）目前只有 DDL，没有 Service/Controller；需求状态必须标「已设计未实现」，不能标「已完成」。

## 3. 角色与场景

### 3.1 角色

| 角色 | 目标 | 痛点 | 主要入口 |
|---|---|---|---|
| 租客 | 找到合适房源、约看、签约、报修、缴费、评价 | 信息不透明、报修没反馈、账单靠催 | 小程序 + Web |
| 房东 | 发布房源、处理约看/申请、收租、处理报修 | 租客筛选无依据、催缴成本高、差评无解释 | Web 为主 |
| 管理员 | 房源核验、评价申诉、字典/菜单维护 | 核验无清单、申诉无流程 | Web 管理端 |
| 平台运营（学生团队兼任） | 造数、演示、监控、答疑 | 没有专职人力，数据是空壳 | Web 大屏 + 运维脚本 |

### 3.2 核心用例

| 编号 | 用例 | 角色 | 触发/前置 | 主流程 | 异常/后置 |
|---|---|---|---|---|---|
| UC-01 | 房源上架 | 房东、管理员 | 房东已登录，房源信息完整 | 发布 → `state=0` → 管理员 8 项核验 → 写 `house_audit` → `state=1` | 核验不通过保持 0；描述变更重审 |
| UC-02 | 搜索看房 | 租客 | 房源 `state=1`、`del_flag=0` | 条件筛选 → 列表 → 详情 → 约看 | 空结果给放宽建议；已租房源不可约 |
| UC-03 | 约看 | 租客、房东 | 房源可租 | 申请 → 房东通过/另选/拒绝 → 看房 → 结束 | 另选被拒进 `state=4`；超时未处理可取消 |
| UC-04 | 签约 | 租客、房东 | 申请通过、押金已付 | 签合同 → 写 `hrent_house_renting`（`status=0`）→ 房源 `state=2` | 合同缺失拒绝；房源已被租则冲突 |
| UC-05 | 退租与评价 | 租客/房东 | 租约 `status=0` | 任一方退租确认 → `status=2`、`actual_end_date` → 30 天内评价 | 第 31 天拒绝；重复评价 409 |
| UC-06 | 报修 | 租客、房东 | 租约生效中 | 提交 → 接单 → 上门 → 完成 → 验收 | 非法跳转 409；重复提交幂等 |
| UC-07 | 账单 | 房东、租客 | 租约生效中 | 生成 → 租客标记已缴（凭证）→ 房东确认 | 重复确认不重复记账；逾期转 OVERDUE |
| UC-08 | AI 选房 | 租客 | 有可租房源 | 条件/自然语言 → 规则抽取 → 检索 → 打分 → 理由 | 模型不可用仍返回 200 |

## 7. 范围边界

### 7.1 本期做

- 存量功能保留：房源浏览/搜索、收藏、约看、租房申请、消息。
- 评分：房源双维 + 房东服务；核验 8 项；贝叶斯；回复；申诉。
- 租约：状态机 + 退租确认 + 日志。
- 报修：6 状态 + 图片 + 日志 + 幂等/乐观锁。
- 账单：生成 + 明细 + 标记已缴 + 房东确认 + 逾期站内信；**不含在线支付**。
- AI：规则抽取 + 标签打分 + 理由 + 三级降级 + 埋点。
- UI：Web 4 页重写 + 8 页换肤；小程序 6 页换肤 + 新增页。
- 工程：Flyway、OpenAPI、监控、备份、回滚。

### 7.2 本期不做

| 项 | 原因 |
|---|---|
| 微信在线支付 | 无商户号 |
| 租客信用评分 | PIPL 第 24 条，缺申诉机制 |
| 小程序提审上架 | 个人主体无房产类目 |
| 向量库 / 独立推荐引擎 | 一期标签规则足够，成本不划算 |
| 暗色模式、地图热力图、Web 全量重写 | 收益低，工时不够 |
| 物理外键 | 与软删/批量迁移冲突，应用层保证 |

### 7.3 二期

租客评分 + 申诉工单、`house_embedding` 向量召回、账单在线支付、多门店/多小区 scope、消息订阅。

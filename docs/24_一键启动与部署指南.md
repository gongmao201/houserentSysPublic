# 一键启动与部署指南

> 版本：v1.0 ｜ 更新：2026-11-11 ｜ 适用：本仓库 `main` 分支
> 目标：把「拉代码 → 跑起来」压缩成一条命令，并让同一套流程在 Windows / macOS / Linux 与服务器上行为一致。

---

## 一、为什么需要这层脚本

在落地一键脚本前，本项目有四个反复出现的问题：

| 问题 | 表现 | 本方案的解法 |
|---|---|---|
| Maven 安装位置不一致 | 同事机器 `mvn` 不在 PATH，或版本不同导致构建结果不一致 | 项目内 Maven Wrapper（固定 3.9.16），`./mvnw` 自动下载 |
| JDK 版本不同 | JDK 8 加 `--add-opens` 直接启动失败；JDK 17 不加则部分反射库报错 | 脚本按 `java -version` 分支拼参数 |
| 平台进程语义不同 | Windows 无 SIGTERM；Git Bash 的 `$!` 不是真实 PID | 存活判断走 `jps`，停止走 `taskkill` |
| 端口/凭据被环境劫持或硬编码 | 云平台注入 `SERVER_PORT` 改端口；口令写死在 `application.yml` | 端口用 `HRENT_PORT` + 显式 `--server.port`；凭据走 `.env` |

## 三、快速开始

### 3.1 前置条件

| 依赖 | 版本 | 校验命令 | 说明 |
|---|---|---|---|
| JDK | 8 及以上，**推荐 17** | `java -version` | JDK 8 可用，但部分反射相关功能在 17 才稳定 |
| MySQL | 5.7 / 8.0 | `mysql --version` | 需提前建好库（默认 `house_rent`），Flyway 会自动建表 |
| Node.js | 16+（推荐 18/20 LTS） | `node -v` | 仅构建前端时需要 |
| Maven | **不需要安装** | — | 项目自带 `mvnw`，首次运行自动下载 |

### 3.2 三步启动

```bash
# ① 准备环境变量（只做一次）
cp .env.example .env          # Windows: copy .env.example .env
# 编辑 .env：至少改 DB_PASSWORD 与 TOKEN_SECRET

# ② 一键启动
./start.sh                    # Linux / macOS / WSL / Git Bash
start.cmd                     # Windows

# ③ 确认
./start.sh status             # 或 start.cmd status
```

**成功时的输出**：

```
[hrent] java version "17.0.14" ... → /usr/bin/java
[hrent] jar 已是最新，跳过构建（加 --rebuild 可强制重建）
[hrent] 启动中：端口 8888，上下文 /hrent，日志 logs/hrent.log
[hrent] 启动成功（PID 12345）
[hrent] 接口地址：http://localhost:8888/hrent
[hrent] 页面地址：http://localhost:8888/hrent/web/index.html
[hrent] 健康检查：http://localhost:8888/hrent/sysCommon/getBaseInfo（POST）
```

**前端怎么起**——两条路，按用途选：

| 用途 | 命令 | 访问地址 | 是否需要 Node |
|---|---|---|---|
| 生产 / 演示（单进程） | `build-web` 构建一次，再 `start` | `http://localhost:8888/hrent/web/index.html` | 只需构建时 |
| 开发（热更新） | `dev` | `http://localhost:8080/` | 是 |

后端启动时若 `hrent-web/dist` 存在，会自动把它映射到 `/hrent/web/**`（`WebMvcConfig` + 环境变量 `HRENT_WEB_DIR`），所以**一个 Java 进程就能同时提供页面和接口**，服务器上不必再装 nginx。前端是 hash 路由且 `assetsPublicPath` 为 `./`，放在 `/hrent/web/` 子路径下可直接工作，不需要服务端 fallback。

`dev` 模式会同时起后端（8888）与 webpack-dev-server（8080），前者由 script 健康检查确认就绪后才起后者；前端用相对路径 `/hrent/**` 请求接口，由 `config/index.js` 的 `proxyTable` 转发到后端，因此代码里没有任何写死的 host/port。

### 3.3 验证服务真的活着

```bash
curl -X POST http://127.0.0.1:8888/hrent/sysCommon/getBaseInfo
# 预期返回 JSON，code 为 "200"
```

> 健康检查用的是 `POST`，不是 `GET`。用 `GET` 会得到 405，不代表服务没起来。

## 四、命令参考

两个平台命令完全一致，只把 `./start.sh` 换成 `start.cmd`。

| 命令 | 作用 | 典型耗时（实测） |
|---|---|---|
| `start` | 构建（如需）→ 后台启动后端 → 健康检查；`dist` 存在时同进程托管前端 | 12.7s（jar 已存在） |
| `dev` | 后端 + 前端开发服务器（热更新） | 后端 12.7s + 前端首次编译 30-60s |
| `run` | 仅前台启动后端，`Ctrl+C` 停止（开发调试） | — |
| `stop` | 停止后端与前端 | 5.2s |
| `restart` | 重启后端（不影响正在跑的前端开发服务器） | 16.6s |
| `status` | 后端 / 前端状态 + 健康检查（后端未运行返回码 1） | < 1s |
| `logs` | 显示后端最近 200 行日志 | — |
| `logs -f` | 持续跟踪后端日志 | — |
| `logs --web` | 查看前端开发服务器日志 | — |
| `build` | 仅构建后端 jar | 1m46s（含下载依赖时更久） |
| `build-web` | 仅构建前端到 `hrent-web/dist` | 2m45s |
| `help` | 显示帮助 | — |

### 4.1 选项

| 选项 | 说明 |
|---|---|
| `--port <n>` | 覆盖后端端口（优先于 `.env` 的 `HRENT_PORT`） |
| `--web-port <n>` | 前端开发服务器端口（默认 8080；被占用时脚本会报出占用者而不是静默换端口） |
| `--web` | 与 `logs` 搭配，查看前端日志 |
| `--no-build` | 跳过构建，直接用现有 jar（离线部署用） |
| `--rebuild` | 强制重新构建 |
| `--with-tests` | 构建时执行单元测试（默认跳过，失败会中断） |
| `--env <file>` | 指定环境变量文件（默认项目根 `.env`） |

### 4.2 返回码

| 命令 | 0 | 非 0 |
|---|---|---|
| `start` / `restart` | 启动成功且健康检查通过 | 端口占用、构建失败、60s 内未通过健康检查 |
| `status` | 运行中 | 未运行 |
| `stop` | 已停止或本来未运行 | 进程无法结束 |
| `build` / `build-web` | 构建成功 | 构建失败 |

> 返回码可直接用于 CI 串联：`./start.sh build && ./start.sh start && ./start.sh status`。

## 五、环境变量（`.env`）

| 变量 | 默认 | 说明 |
|---|---|---|
| `HRENT_PORT` | `8888` | 服务端口。**不要改成 `SERVER_PORT`/`PORT`**，见 6.1 |
| `HRENT_WEB_PORT` | `8080` | 前端开发服务器端口（仅 `dev` 用；优先级：`--web-port` > 本变量 > 8080） |
| `HRENT_WEB_DIR` | 自动 | 前端产物目录。`dist` 存在时脚本自动设置并映射到 `/hrent/web/**`，一般不用手填 |
| `DB_URL` | `jdbc:mysql://127.0.0.1:3306/house_rent?...` | JDBC 连接串 |
| `DB_USERNAME` | `root` | 数据库账号 |
| `DB_PASSWORD` | `change-me` | 数据库口令，**必须改** |
| `TOKEN_SECRET` | `change-me-...` | JWT 签名密钥，生产环境用 `openssl rand -base64 32` 生成 |
| `WECHAT_APP_ID` | 空 | 小程序 AppID，留空时微信登录接口返回明确错误，不会伪造登录 |
| `WECHAT_APP_SECRET` | 空 | 小程序 AppSecret |
| `JAVA_OPTS` | `-Xms256m -Xmx512m -Dfile.encoding=UTF-8` | JVM 参数，2C4G 服务器建议 `-Xmx512m` |

脚本把 `DB_*` / `TOKEN_SECRET` / `WECHAT_*` 转成 Spring Boot 识别的环境变量（`SPRING_DATASOURCE_*`、`TOKEN_SECRET`、`WECHAT_APP_ID`）后再启动，因此**不需要改 `application.yml`**。

> `.env` 已在 `.gitignore` 中，不会入库。`.env.example` 只含占位符。

## 六、平台差异与设计决策（均为实测结论）

### 6.1 端口只认 `HRENT_PORT`

Spring Boot 会把环境变量 `SERVER_PORT` 绑定到 `server.port`。实测某 CI 沙箱注入 `SERVER_PORT=52051`，服务直接起在 52051 并因端口占用启动失败。

因此脚本：
- 自身只用 `HRENT_PORT` 作为配置键；
- 启动时显式追加 `--server.port=<port>`（命令行参数优先级高于环境变量）。

### 6.2 Git Bash 下 `$!` 不是真实 PID

Windows 上 Git Bash（MSYS2）执行 `nohup java ... &` 后，`$!` 拿到的是 MSYS 包装进程号（如 767），而真实 Java 进程是另一个 Windows PID（如 25324）。后果：`kill -0 767` 恒失败，`status` 误报「未运行」。

实测同时确认：Git Bash 的 `ps` 不支持 `-o` 选项，`kill` 也不认 Windows 原生 PID。

因此脚本：
- 存活判断优先用 `jps -l` 匹配 jar 名（`jps` 输出的是 Windows PID）；
- `jps` 不可用时按监听端口反查，且**必须校验该 PID 是 Java 进程**（见 6.3）；
- 停止时 Windows 分支走 `taskkill //F //PID`。

### 6.3 端口反查必须校验进程名

早期实现直接用 `netstat -ano` 取占用端口的 PID。实测被一个监听 8890 的 Python 进程骗过：脚本把它当成「服务已在运行」，于是拒绝启动，而不是报「端口被占用」。

修正后：反查到的 PID 必须通过 `tasklist`（Windows）或 `ps -o comm=`（Unix）确认为 Java 进程，否则视为「未运行」。这样错误信息才能指向真正的原因。

### 6.4 Windows 停止只能强杀

Windows 没有 SIGTERM 语义。实测 `taskkill /PID <pid>`（不带 `/F`）对无窗口的控制台 Java 进程无效，脚本会空等 15 秒再强杀。

因此 Windows 分支直接 `taskkill /F /PID`，并把等待缩短到 6 秒。数据一致性由 MySQL 事务保证（未提交事务会回滚）；代价是 JVM shutdown hook 不会执行，连接池不做优雅关闭。

Linux/macOS 仍走 `kill -TERM` → 等 15 秒 → `kill -9`。

### 6.5 PowerShell 5.1 的两个坑

**坑一：`java -version` 的输出走 stderr。** 在 `$ErrorActionPreference = 'Stop'` 下用 `2>&1` 捕获会被当成异常抛出，脚本直接报「无法执行 java -version」。改用 `System.Diagnostics.Process` 重定向读取 stdout/stderr。

**坑二：环境变量大小写冲突。** Git Bash 会同时注入 `HTTPS_PROXY` 和 `https_proxy`。PowerShell 5.1 的 `Start-Process` 内部字典大小写敏感，遇到重复键直接抛「字典中的关键字冲突」，启动失败。脚本在启动前清理重复键（保留大写形式）。

### 6.6 `Get-NetTCPConnection` 无匹配会抛异常

`Get-NetTCPConnection -LocalPort X -State Listen -ErrorAction Stop` 在没有监听时会抛「找不到任何匹配的 MSFT_NetTCPConnection 对象」，而不是返回空。若不处理，会被误判为 cmdlet 不可用而走 netstat 兜底。

脚本的处理：cmdlet 能用就以它为准；只有 cmdlet 本身不可用时才退回 netstat，且 netstat 必须过滤 `LISTENING` 状态（否则 `TIME_WAIT` 的历史连接会被当成端口占用）。

### 6.7 状态判定以健康检查为准

端口监听状态在启动瞬间和 `TIME_WAIT` 残留期会波动，`status` 一度误报「端口未监听，可能仍在启动」，而实际上接口已可访问。

现在 `status` 先做健康检查（HTTP 请求），通过即判定「运行中」；端口监听只作为辅助信息，在健康检查失败时才用于区分「端口没起」和「端口起了但接口无响应」。

### 6.8 日志轮转

每次 `start` 前，把 `logs/hrent.log` 轮转为 `logs/hrent.log.1`（只保留一份历史），避免长期运行后日志无限增长。

Windows 侧因为 `Start-Process` 的重定向只能覆盖写，额外产生 `hrent.err.log`（JVM 自身错误，如启动参数错、找不到主类）；应用日志仍在 `hrent.log`。

### 6.9 批处理入口必须是纯 ASCII + CRLF

`cmd.exe` 解析 `.cmd` 时使用**当前控制台代码页**（中文 Windows 为 936/GBK），而不是文件自身的编码。`start.cmd` 原先保存为 UTF-8 无 BOM，中文 `REM` 注释被按 GBK 解码成乱码，乱码字节又破坏了 `REM` 的边界，导致注释后半段被当作命令执行——这就是双击时刷出一屏「不是内部或外部命令」并闪退的直接原因。

因此定下两条硬约束：

1. `start.cmd` **只写 ASCII**，任何中文提示都放进 `hrent.ps1`（PowerShell 按 UTF-8 BOM 读取，不受控制台代码页影响）；
2. `start.cmd` 保持 **CRLF**（`.gitattributes` 已声明 `*.cmd text eol=crlf`，避免 Linux/macOS 检出后带 LF 或反向污染）。

另外，`%CMDCMDLINE%` 不能用来判断「是否双击」：真实双击时它的值是 `cmd /c ""C:\path\start.cmd" "`，赋值给 `set "VAR=..."` 会因为嵌套引号被截断。最终采用更简单且无歧义的规则：**无参数运行就保留窗口，带参数运行不阻塞**。

## 七、服务器部署

### 7.1 目录约定

```
/opt/hrent/
├── .env                       # 权限 600，属主 hrent
├── hrent-api/                 # 后端代码 + target/hrent-0.0.1-SNAPSHOT.jar
├── web/                       # 前端构建产物（hrent-web/dist 的内容）
└── logs/                      # 用脚本启动时的日志目录
```

### 7.2 后端：systemd

```bash
# 专用低权限用户（不要用 root 跑服务）
sudo useradd -r -s /sbin/nologin hrent
sudo mkdir -p /opt/hrent && sudo chown -R hrent:hrent /opt/hrent

# 代码与配置
sudo cp -r . /opt/hrent/ && cd /opt/hrent
sudo cp .env.example .env && sudo chmod 600 .env && sudo chown hrent:hrent .env
sudo vi .env                                  # 填真实口令与密钥

# 构建（只需要 JDK 17，不需要装 Maven）
cd /opt/hrent/hrent-api && sudo -u hrent ./mvnw -DskipTests clean package

# 安装服务
sudo cp /opt/hrent/deploy/hrent.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now hrent
sudo systemctl status hrent
```

**关键点**：`deploy/hrent.service` 里的 JVM 参数是直接写死的，没有用 `$JAVA_OPTS` 变量。因为 systemd 不做 shell 词分割，含多个参数的变量会被当成**一个**参数传给 java，启动必然失败。改内存上限请直接改 `ExecStart`。

```bash
# 常用运维命令
sudo journalctl -u hrent -f          # 实时日志
sudo systemctl restart hrent         # 重启
sudo systemctl stop hrent            # 停止
```

### 7.3 前端：两种部署方式

**方式 A（推荐，单进程）**——后端直接托管 `dist`，不需要 nginx：

```bash
cd /opt/hrent/hrent-web
npm install
NODE_OPTIONS=--openssl-legacy-provider npm run build    # Node 17+ 必须加该开关

# 启动后端时指向产物目录（脚本会自动设置 HRENT_WEB_DIR，手动启动时需自己给）
HRENT_WEB_DIR=/opt/hrent/hrent-web/dist ./start.sh --no-build
# 访问 http://<host>:8888/hrent/web/index.html
```

`WebMvcConfig` 把 `HRENT_WEB_DIR` 映射到 `/hrent/web/**`；未设置时回退到「运行目录上一级的 `hrent-web/dist`」。前端是 hash 路由，路径由 `#` 承载，因此不需要任何 fallback 规则。

**方式 B（nginx 托管，适合多站点/需要 HTTPS/CDN）**：

```bash
cd /opt/hrent/hrent-web
npm install
NODE_OPTIONS=--openssl-legacy-provider npm run build    # Node 17+ 必须加该开关
sudo mkdir -p /opt/hrent/web && sudo cp -r dist/* /opt/hrent/web/

sudo cp /opt/hrent/deploy/nginx.conf.example /etc/nginx/conf.d/hrent.conf
sudo nginx -t && sudo systemctl reload nginx
```

**关键点**：`proxy_pass` 后面**不带 URI 后缀**（写 `http://127.0.0.1:8888;` 而不是 `.../hrent/;`），原始路径 `/hrent/xxx` 原样转发，不会因为多写/少写斜杠导致 404。

### 7.4 HTTPS

```bash
sudo apt install certbot python3-certbot-nginx     # Debian/Ubuntu
sudo certbot --nginx -d your-domain.com            # 自动改写 nginx 配置并配置续期
```

### 7.5 上线前检查

- [ ] `.env` 权限为 `600`，属主为服务用户，且 `git status` 看不到它
- [ ] `TOKEN_SECRET` 已替换为随机值（不是 `change-me-...`）
- [ ] `DB_PASSWORD` 已替换，且该账号只有 `house_rent` 库权限（不要用 root）
- [ ] 反向代理的 `client_max_body_size` = 10m（报修/评价多图上传，低于默认 1m 会 413）
- [ ] 防火墙只放行 80/443，8888 不对公网暴露
- [ ] 已配置数据库定时备份（`mysqldump` + 异地存储）
- [ ] `journalctl -u hrent` 里没有反复重启记录

### 8.3 修复的缺陷（全部实测暴露）

| # | 缺陷 | 根因 | 修复 |
|---|---|---|---|
| 1 | `status` 误报未运行 | Git Bash 的 `$!` 是 MSYS PID，非真实 PID | 改用 `jps -l` 匹配 jar 名 |
| 2 | 非 Java 进程占端口时误判「已在运行」 | 端口反查未校验进程名 | 加 `tasklist`/`ps` 校验 |
| 3 | Windows 停止空等 15 秒 | `taskkill` 不带 `/F` 对无窗口 Java 无效 | Windows 直接 `/F`，等待缩短到 6 秒 |
| 4 | PowerShell 报「无法执行 java -version」 | `2>&1` 在 `$ErrorActionPreference='Stop'` 下抛异常 | 改 `System.Diagnostics.Process` 重定向 |
| 5 | PowerShell 启动崩在 `Start-Process` | 代理变量大小写重复导致内部字典冲突 | 启动前归一化环境变量 |
| 6 | PowerShell 端口误判占用 | netstat 兜底匹配到 `TIME_WAIT` | cmdlet 优先 + 兜底过滤 `LISTENING` |
| 7 | `status` 误报「端口未监听」 | 判定顺序把端口检测放在健康检查前 | 改为健康检查为主、端口为辅 |
| 8 | **双击 `start.cmd` 闪退** | 文件为 UTF-8 无 BOM + LF，cmd 按 GBK 解析，中文 `REM` 乱码后被拆成命令执行 | `start.cmd` 改为**纯 ASCII + CRLF**，中文提示全部交给 `hrent.ps1` |
| 9 | **双击后看不到任何结果** | 脚本结束后窗口立即关闭 | 无参数运行时窗口保留；失败时打印原因 + 日志路径 |
| 10 | **重复双击被当失败** | 「服务已在运行」走 `Die`（返回码 1） | 改为幂等成功（返回码 0），并从进程命令行取真实端口 |
| 11 | **健康检查假阳性（最隐蔽）** | `curl -s` 遇 4xx/5xx 仍返回 exit 0，且未禁用代理；系统存在 `http_proxy` 时本机请求被代理截获返回 `502`，服务根本没起来也判「健康」 | `--noproxy "*"` + `-w %{http_code}` 严格校验 200 |
| 12 | **`.env` 占位符静默生效** | `.env` 从模板复制后 `DB_PASSWORD=change-me` 未替换，脚本原样注入 `SPRING_DATASOURCE_PASSWORD`，Spring 连库抛 `1045` | 启动前检测 `^change[-_]?me` 直接拦截，明确指出要改哪一行 |
| 13 | **`status` 误报「运行中」** | 只判断 PID 是否存在，进程退出后 PID 被系统复用给其他程序 | 与 `Start-App` 一致，校验进程名是 `java`，否则判「未运行」 |

> 第 11 条是排查过程中最误导人的一个：因为健康检查假阳性，`start` 会把「进程已退出」误报成「启动成功」，让人以为服务在跑。

### 8.5 数据库认证失败与健康检查修复验证（2026-11-11 三次修复）

现象：双击后窗口不再闪退（B12 生效），但显示 `Access denied for user 'root'@'localhost' (using password: YES)`。

**根因链（实测）**：

| 环节 | 实测结果 |
|---|---|
| `.env` 第 26 行 | `DB_PASSWORD=change-me`（模板占位符，从未替换） |
| 用该密码连 MySQL | `ERROR 1045 (28000): Access denied` |
| 用 `<LOCAL_DB_PASSWORD>` 连 MySQL | `ok / 1`（`application.yml` 里的本地默认值才是真实密码） |
| 脚本行为 | `Set-SpringEnv` 把 `change-me` 注入 `SPRING_DATASOURCE_PASSWORD`，覆盖了 `application.yml` 的 `<LOCAL_DB_PASSWORD>` |
| 健康检查 | 带代理 `curl` 返回 `502` 但 `exit=0` → 旧逻辑判「健康」；禁代理后 `http=000 exit=7` → 正确判「不健康」 |

**修复后验证**：

| # | 用例 | 结果 |
|---|---|---|
| 1 | 占位符拦截 | `.env` 设为 `change-me` 时启动，**1 秒内**报「DB_PASSWORD 仍是模板占位符」，不再等 Spring 抛栈 |
| 2 | 真实启动 | 密码改回 `<LOCAL_DB_PASSWORD>`，日志出现 `Started HrentApplication in 8.253 seconds`，无 `Access denied` |
| 3 | 健康检查（服务在跑） | `--noproxy` + 状态码校验 → 200 判定通过 |
| 4 | 健康检查（服务未跑） | 旧写法 `exit=0` 判「健康」（假阳性）；新写法 `http=000 exit=7` 判「不健康」 |
| 5 | `TOKEN_SECRET` 占位符 | 只告警不阻塞：`TOKEN_SECRET 仍是模板占位符，建议换成 32 字节以上随机值` |

## 九、故障排查

| 现象 | 原因 | 处置 |
|---|---|---|
| `未找到 java` | 未装 JDK 或 `JAVA_HOME` 未设置 | 装 JDK 17，或 `export JAVA_HOME=/path/to/jdk` |
| `Java 版本过低（major=7）` | JDK 太旧 | 升级到 JDK 8+，推荐 17 |
| `缺少 hrent-api/mvnw` | 拉的是旧提交，Wrapper 未入库 | `git pull` 到含 Wrapper 的版本 |
| 构建卡在 `Downloading` | 首次下载 Maven 发行版与依赖，或网络受限 | 换网络/配镜像；离线机器用 `--no-build` 直接跑已有 jar |
| `端口 8888 已被占用` | 有旧进程或其他服务占用 | 按提示的 PID 处理，或 `--port 8889` 换端口 |
| `No such process` 但服务在跑 | 在 Git Bash 里手工 `kill $!` | 用 `./start.sh stop`，不要手工 kill MSYS PID |
| 启动后立刻退出，日志有 `Access denied for user 'root'@'localhost' (using password: YES)` | `.env` 的 `DB_PASSWORD` 与 MySQL 实际密码不一致；最常见是仍为模板占位符 `change-me` | 改成真实密码（本机 MySQL 默认 `<LOCAL_DB_PASSWORD>`）后 `restart`。新版启动前会拦截占位符并直接指出该行 |
| `status` 说健康检查通过，浏览器却打不开 | 旧版健康检查被系统代理劫持：`http_proxy` 把 `127.0.0.1` 也发给代理，代理回 `502` 而 `curl` 仍 `exit 0` | 升级脚本（已加 `--noproxy "*"` + 状态码 200 校验）；临时可用 `curl --noproxy "*" http://127.0.0.1:8888/hrent/...` 自查 |
| `Communications link failure` | MySQL 未启动或端口不通 | 启动 MySQL，确认 `DB_URL` 的 host/port |
| `Unknown database 'house_rent'` | 库未创建 | `CREATE DATABASE house_rent DEFAULT CHARSET utf8mb4;`（Flyway 只建表不建库） |
| `status` 显示运行中但接口 404 | 漏了上下文路径 `/hrent` | 访问 `http://localhost:8888/hrent/...` |
| **双击 `start.cmd` 窗口一闪就没了** | 旧版入口是 UTF-8 中文注释，cmd 按 GBK 解析后乱码被当命令执行；且脚本结束即关窗 | 已修复（入口纯 ASCII + CRLF、无参数运行保留窗口）。若升级后仍闪退，直接看 `logs\hrent.error.log` 首行 |
| 双击后窗口停住并显示 `FAILED` | 启动失败，原因已打印在窗口上方 | 按提示处理（数据库未启动 / 口令错误 / 端口占用），或 `start.cmd logs` 看完整日志 |
| PowerShell 中文乱码 | `hrent.ps1` 被编辑器改成无 BOM UTF-8 | 用支持 UTF-8 BOM 的编辑器另存。注意 `start.cmd` 相反：**必须保持纯 ASCII + CRLF**，不能写中文注释 |
| `无法加载文件 ... 未数字签名` | PowerShell 执行策略 | 用 `start.cmd`（已带 `-ExecutionPolicy Bypass`），不要直接双击 `.ps1` |
| 启动成功但打开页面 404 | `hrent-web/dist` 未构建，后端没有可托管的文件 | 先 `start.cmd build-web`（或 `npm run build`），再 `restart` |
| 页面能开、接口全 404 | 前端请求的是相对路径 `/hrent/**`，被放在了站点根以外 | 页面必须从 `http://<host>:8888/hrent/web/index.html` 访问；若用 nginx 单独托管，需把 `/hrent/` 反代到后端 |
| `dev` 起不来，提示端口 8080 被占用 | 上一次 dev server 未退出，或 8080 被别的程序占用 | 脚本会打印占用者 PID；`start.cmd stop` 清理，或 `--web-port 8081` |
| `dev` 报 `ERR_OSSL_EVP_UNSUPPORTED` | Node 17+ 的 OpenSSL 3 移除了 webpack 3 依赖的 md4 | 不用手工加参数，脚本已设 `NODE_OPTIONS=--openssl-legacy-provider`；手工跑时必须自己加 |
| 改前端代码页面不刷新 | 打开的是单进程地址（8888 托管的是构建产物） | 开发请用 `start.cmd dev` 访问 8080；改完再 `build-web` 才会更新 8888 上的页面 |

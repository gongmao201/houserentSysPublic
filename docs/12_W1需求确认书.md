## 一、四个必须当场拍板的问题

### 问 1 · AI 到底要"能看见的模型"，还是要"线上能跑"？

| 选项 | 含义 | 代价 |
|---|---|---|
| A（推荐）**双形态** | 演示时用真模型（qwen2.5:3b，本机跑）；线上走规则引擎 + 模板文案，零 GPU 成本 | 线上没有大模型；演示有 |
| B 全线上模型 | 需要 32GB 内存机器（云上约 ¥600–900/月） | 成本高，且答辩/演示期后无人续费 |
| C 只做规则 | 不提 AI 模型 | 需求 1 名不副实 |

**甲方选择：☐ A　☐ B　☐ C**　　（选 B 请注明预算来源：__________）

> 说明：4C8G 服务器（¥150–250/月）装不下 7B 模型，这是物理限制，不是实现问题。选 A 时，演示环节会真实调用模型，评委/甲方可现场看到输出。

### 问 2 · 交付物是"一个能扫码的东西"，还是"一套能自己跑起来的东西"？

| 事实 | 影响 |
|---|---|
| 微信体验版**必须**绑定已备案域名 + HTTPS | 备案需 1–3 周，且个人主体无法开通房产类目 |
| 开发者工具预览二维码**约 25 分钟失效** | 不能作为可分发交付物 |

**本期交付（三件套）：**
1. **3 分钟演示录屏**（1080p，可随时播放）
2. **一键启动包**：`docker compose up -d` + 10 行 README（甲方/评委可在自己电脑复现）
3. **10 分钟演示脚本**（逐步骤 + 每步讲解词 + 三个失败场景的降级路径）

现场演示时附带二维码（扫码即用，但仅限当场）。

**甲方确认：☐ 接受三件套　☐ 必须提供可扫码分发的版本（则需先完成域名备案，交付时间顺延）**

### 问 3 · 评分是"双向"还是"房源 + 房东两维"？

原需求写"官方评审 + 用户评审并存，帮房东筛租客、租客筛房东"。

| 本期做 | 本期不做 |
|---|---|
| 房源评分（平台核验 8 项 × 0.4 + 用户评价 × 0.6，含冷启动平滑） | **租客信用评分**（对自然人的自动化决策，需配套申诉机制） |
| 房东服务评分（资质核验 × 0.3 + 用户评价 × 0.7） | |
| 房东侧替代信号（4 个可见字段）：**资料完整度 / 历史租约次数 / 欠租记录 / 实名状态** | |

**甲方确认：☐ 接受（租客信用评分列二期）　☐ 不接受，要求一期做（需追加 2 周 + 法务评估）**

### 问 4 · "性能优化 / 老旧配置升级"是指换机器，还是改代码？

| 理解 | 本期方案 |
|---|---|
| 改代码（乙方默认理解） | 框架升级 + SQL 索引 + 缓存 + 前端体积 + 压测对比 |
| 换机器（甲方可能的本意） | 需明确预算与规格；若给到 8C32G，AI 可上线（问 1 直接选 B） |

**甲方选择：☐ 改代码　☐ 换机器（预算 ¥______/月，规格 ________）　☐ 两者都要**

## 二、本期交付清单（做）

| 模块 | 内容 |
|---|---|
| 存量功能 | 房源浏览/搜索、收藏、约看、租房申请、消息（全部保留，回归 diff 0 差异） |
| 评分 | 房源双维评分、房东服务评分、评价提交（租约结束后 30 天内）、申诉入口 |
| 报修 | 提交（多图）、接单、上门、完成、验收，全状态机 + 流转日志 |
| 账单 | 按月生成、租客标记已缴（附凭证）、房东确认、逾期站内信（**不含在线支付**） |
| AI | 结构化条件推荐 + 推荐理由（演示真模型 / 线上模板），可降级 |
| UI | Web 4 页重写 + 8 页换肤 + 数据大屏；小程序 6 页换肤 + 6 个新页面 |
| 工程 | Flyway 迁移、OpenAPI 文档、Docker Compose、监控告警、备份与回滚 |

## 三、本期明确不做（避免 W12 争议）

1. 微信在线支付（无商户号，二期）
2. 租客信用评分（一期，见问 3）
3. 小程序提审上架 / 线上运营 / 真实用户灰度
4. 暗色模式、地图热力图、Web 全量重写
5. 向量数据库 / 独立推荐引擎

## 四、验收方式

按 `00` 文档第七章 **12 条验收清单**逐条现场演示，其中 5 条为硬门槛：

| # | 硬门槛 |
|---|---|
| 1 | 老功能回归：40+ 接口快照 diff 0 差异 |
| 2 | 数据迁移：金额汇总相等 + 抽样 100 行一致 + 老密码可登录 |
| 3 | 评分：0 评价房源显示"新上"且分 ≥3.0；退租后第 31 天拒绝提交 |
| 4 | AI：关掉模型仍返回结果（不 500）；`ai.mode=rule` 全流程可跑 |
| 5 | 运维：停服 1 分钟内告警；代码回滚 ≤30 分钟（现场演练） |

## 五、变更规则

- W1 之后新增需求 → 进二期 backlog，不进本期排期。
- 任何变更需甲方书面（微信文字亦可）确认，并同步调整排期。
- 团队 5 人、12 周为固定约束；需求增加意味着范围等量削减。

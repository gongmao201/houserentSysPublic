## 二、架构与隔离策略

```
[Vue2 + ElementUI 管理端]
   └─ src/network/v2.js（token / 解包 / 600 跳登录 / 300ms 去重）
        │  HTTP 200 + {code,message,data,traceId}
        ▼
[Spring Boot 2.5.5]
   ├─ 存量 14 Controller  ── 原样不动（字符串 code 的 ResponseResult）
   └─ api/v2（本次新增，物理隔离）
        ├─ V2TraceFilter → traceId + 耗时
        ├─ V2Context     → 严格鉴权 / 越权 403
        ├─ Controller    → 只做参数传递
        ├─ Service       → 业务规则 / 状态机 / 幂等
        ├─ V2Mapper      → v2 专用 SQL（参数化）
        └─ 已有 Dao       → 复用 V3–V7 迁移的 12 张新表
```

**三条底线**：存量接口路径/参数/响应结构不改；新接口一律 `/api/v2`；异常处理用 `@RestControllerAdvice(basePackages="com.wt.hrentSystem.api.v2")` 限定作用域，不会改变存量异常行为。

## 三、后端模块功能

### 3.1 评分 `/api/v2/rating`（6 个接口）

| 接口 | 方法 | 功能 |
|---|---|---|
| `/submit` | POST | 提交评价（房源 / 房东） |
| `/house/{houseId}` | GET | 房源评分汇总 + 评价列表 |
| `/landlord/{landlordId}` | GET | 房东服务评分 |
| `/{id}/reply` | POST | 房东回复（每条一次，≤100 字） |
| `/{id}/appeal` | POST | 被评方申诉 → `APPEALING` |
| `/audit` | POST | 管理员平台核验（8 项加权） |

业务规则：
1. **评价资格链**：租约 `status=TERMINATED` → `actualEndDate` 非空 → `今天 ≤ 退租日+30 天` → 评价对象与租约 houseId/landlordId 一致 → 评价人必须是租客本人（管理员不豁免）。违反分别返回 404 / 422 / 403。
2. **唯一性**：应用层查 `review` + DB 唯一键 `uk_reviewer_target` 双兜底，重复提交 409。
3. **展示分** = `0.4×平台核验分 + 0.6×贝叶斯平滑用户分`，先验 `C=3, m=4.0`；`reviewCount<3` 时 `isNew=true` 且展示分 4.0（满足「0 评价房源 ≥3.0」硬门槛）。申诉中 / 隐藏评价不计入均分。
4. **核验权重**：照片真实 0.20、地址可核验 0.20、设施一致 0.15、价格合理 0.15、合同已上传 0.10、消防安全 0.10、押付规则 0.05、无投诉 0.05，合计 1.00。
5. 评价列表用户名脱敏为「张**」，图片 ≤3 张、内容 ≤500 字、score 1.0–5.0 最多 1 位小数。

### 3.2 租约 `/api/v2/lease`（3 个接口）

| 接口 | 方法 | 功能 |
|---|---|---|
| `/{id}` | GET | 详情（状态、起止日、实际退租日、月租分） |
| `/mine` | GET | 我的租约（租客 / 房东按角色过滤，支持 status 与分页） |
| `/{id}/terminate` | POST | 退租确认，写 `lease_log`，返回 `reviewWindowUntil` |

状态映射（DB `TINYINT` ↔ 接口字符串）集中在 `LeaseService`：`0 ACTIVE / 1 EXPIRED / 2 TERMINATED / 3 CANCELLED`。`terminate` 用 `version` 乐观锁，影响行数 0 → 409；重复确认 409。

### 3.3 报修 `/api/v2/repair`（8 个接口）

| 接口 | 方法 | 功能 |
|---|---|---|
| `/` | POST | 创建工单（多图、`Idempotency-Key` 幂等） |
| `/mine` | GET | 我的工单（租客看自己、房东看自己房源，分页） |
| `/{id}` | GET | 详情 + `logs[]` 时间线 + `images[]` |
| `/{id}/accept` | POST | 接单 `CREATED→ACCEPTED` |
| `/{id}/arrive` | POST | 上门 `ACCEPTED→ON_SITE` |
| `/{id}/complete` | POST | 完成 `ON_SITE→COMPLETED`（可附完工图） |
| `/{id}/confirm` | POST | 租客验收 `COMPLETED→ACCEPTED_BY_TENANT` |
| `/{id}/cancel` | POST | 取消 `CREATED→CANCELLED`（待定 T-03 严格口径） |

- 5 个动作统一路由 `POST /{id}/{action}`，action 白名单校验，未知动作 400；非法跳转 409 且 message 写明当前/期望状态。
- 状态流转一条 SQL 完成 `status + version + 时间字段`，`where version=? and status=?`，抢单失败返回 409。
- 每次流转写 `repair_log`（from/to/操作人角色/备注）；图片分 `SUBMIT` / `COMPLETE` 两阶段。
- 角色：接单/上门/完成限房东或管理员；验收/取消限租客或管理员。

### 3.4 账单 `/api/v2/bill`（6 个接口）

| 接口 | 方法 | 功能 |
|---|---|---|
| `/generate` | POST | 房东按月生成（`(renting_id, period)` 唯一 → 409） |
| `/mine` | GET | 我的账单（period / status 筛选 + 分页） |
| `/{id}` | GET | 详情含 `items[]`，校验明细合计 |
| `/{id}/mark-paid` | POST | 租客线下转账后标记 `UNPAID→MARKED` |
| `/{id}/confirm` | POST | 房东确认 `MARKED→PAID` |
| `/pending` | GET | 房东待确认队列 |

- 金额全链路 `long fen`，生成时同步写一条 `RENT` 明细；详情 `SUM(items.amountFen) != amountFen` → **500 + error 日志**，不静默放过对账错误。
- 逾期按 `payable_time < NOW()` 动态判定，兼容 V5 已落库的 `OVERDUE`（待定 T-09）。
- 重复确认返回 200 且 `idempotentHit=true`，不累加金额；标记金额不得超过应收。

### 3.5 AI 推荐 `/api/v2/ai`（3 个接口）

| 接口 | 方法 | 功能 |
|---|---|---|
| `/recommend` | POST | 结构化条件推荐，返回 `{mode,intent,list,total}` |
| `/reason` | POST | 理由补全（本期模板文案） |
| `/feedback` | POST | 埋点（IMPRESSION / CLICK / APPLY） |

- `mode=rule`：filters 优先，中文 query 规则补空（预算 / 几房 / `XX区` / 养宠 / 地铁 / 电梯 / 采光）→ 参数化检索 → 加权打分 → 模板理由。
- **模型不可用时仍返回 200**；无结果时后端自动放宽预算 20% 并把提示放顶层 `message`。
- 埋点 query 入库前做手机号掩码，不存明文；`recommend`/`reason` 允许匿名演示，`feedback` 强制登录。

### 3.6 文件 `/api/v2/file`（1 个接口）

`POST /upload`：扩展名 + Content-Type 双白名单（jpg/jpeg/png/webp）、≤5MB、UUID 重命名（丢弃原始文件名、防路径穿越）、目录由 `file.local` 配置化、落盘失败记日志后 500。压缩/缩略图未实现（待定 T-05），显式返回 `compressed=false` 与 `width/height=null`，不伪造数据。

## 五、全局约定

| 项 | 约定 |
|---|---|
| 响应体 | `{code:int, message, data, traceId}`；HTTP 恒 200（网关级错误除外） |
| 业务码 | 200 成功 / 400 参数 / 403 越权 / 404 不存在 / 409 冲突 / 422 业务校验 / 429 频控 / 500 服务异常 / **600 未登录**（沿用存量，不改 401） |
| 分页 | `pageNo`(从 1) / `pageSize`(默认 10，上限 50) / `count` / `list`；空结果返回 `[]` |
| 金额 | 接口层整数「分」；DB 老 `money` 元字段只读；展示层 `(fen/100).toFixed(2)` |
| 时间 | ISO-8601 带时区（`2026-11-11T10:00:00+08:00`），日期 `yyyy-MM-dd` |
| 枚举 | 大写字符串，禁止魔法数字；租约数字↔字符串映射只在 Service 一处 |
| 幂等 | 写接口 `Idempotency-Key` / 唯一索引 / `version` 乐观锁 |
| 鉴权 | 请求头 `token: <jwt>`（兼容 `Authorization: Bearer`），v2 严格拒绝匿名（AI 两接口例外） |

## 六、安全与可靠性

1. **越权**：每个接口第一行校验 owner，返回 403 而非 404（避免猜 ID 探测）；管理员仅豁免资源访问，不豁免评价资格。
2. **SQL**：全部 `#{}` 参数化；`LIKE` 用 `CONCAT('%',#{x},'%')`；`orderBy` 白名单固化在 XML，不拼接 SQL。
3. **异常**：`@RestControllerAdvice` 只作用于 v2；未捕获异常记完整堆栈到日志，前端只拿 code=500 + traceId，不返回堆栈/SQL。
4. **日志脱敏**：不打印 token/密码/手机号；评价用户显示「张**」；埋点 query 手机号掩码。
5. **上传**：扩展名 + MIME 双校验、大小限制、UUID 重命名、`normalize()+startsWith(dir)` 防穿越。
6. **无界增长**：租约列表 SQL `LIMIT 200` 后内存分页；请求去重 Map 用 `setTimeout` 300ms 清理，不长期累积。
7. **凭据**：数据库口令、JWT secret、微信 appSecret 走配置文件/环境变量，代码内无硬编码凭据（存量 `src/config.js` 的地图 Key 属历史债务，见待定 T-08）。

## 七、运行方式

```bash
# 后端（联网机器，推荐）
cd hrent-api
mvn clean package -DskipTests
mvn spring-boot:run
# 预期：Started HrentApplication；Flyway: Successfully validated 8 migrations
# 地址：http://localhost:8888/hrent/api/v2/...  （8888 + context-path /hrent）

# 前端
cd hrent-web
npm install
npm run dev                                      # 开发
NODE_OPTIONS=--openssl-legacy-provider npm run build   # Node 17+ 生产构建
```

登录管理端后从左侧「新功能 v2」菜单进入 4 个页面。v2 接口需先登录拿 token（AI 推荐/理由除外）。

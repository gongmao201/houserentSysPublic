## 三、契约先行 + Mock 并行（核心节奏）

**问题**：v1 是"BE 一周做完一个模块 → FE/MP 再联调"，串行浪费 3 周。

**做法**：
- W2 末 BE **一次性**输出全部 OpenAPI spec（老业务 + 评分 + 报修 + 缴费 + AI）。
- 用 Apifox/Prism 起 mock server，FE/MP 从 W3 起并行开发，**不等真接口**。
- 真接口上线后只做"替换 baseURL + 联调"。
- W2 产出 `design/tokens.json` 单一来源 → 生成 `tokens.css` 与 `app.wxss`，双端只消费生成物。

### 3.1 契约冻结表

| 契约 | 冻结时间 | 冻结人 | 消费方 | 变更规则 |
|---|---|---|---|---|
| 老业务 API（房源/用户/约看/消息） | W2 末 | BE | FE、MP | 不改，只加字段 |
| 评分 API | W2 末（随全量 spec） | BE | FE、MP | 版本 +0.0.1，群内 @ |
| 报修 API | W2 末 | BE | FE、MP | 同上 |

## 四、API 版本化

- 老接口保留 `/api/**`，保证老小程序在线版本不 500。
- 新模块走 `/api/v2/**`。
- 统一响应体 `{ code, message, data, traceId }` **仅 v2 启用**；老接口响应结构不动。

## 五、共用数据约定（v2.1 恢复，v2 误删）

| 项 | 约定 |
|---|---|
| 时间格式 | ISO-8601 `yyyy-MM-dd'T'HH:mm:ssXXX`；DB 时区 Asia/Shanghai |
| 金额 | **接口层一律"分"（BIGINT）**；DB 老字段元（DOUBLE）只读，新字段 `*_fen` |
| 评分 | 0~5 浮点，保留 1 位小数；展示分 = 贝叶斯平滑后 |
| 图片 | 后端返回完整 URL；列表用缩略图 URL（`?w=400`） |
| 分页 | **`pageNo`（从 1 开始）+ `pageSize`（默认 10）+ `count` + `list`**（沿用存量字段名，与 13 号文档一致） |
| 响应体 | v2：`{code, message, data, traceId}`；老接口原样 |
| 枚举 | 状态值用字符串常量（`CREATED`/`ACCEPTED`...），不用魔法数字 |

## 七、沟通机制

- **每日站会** 10:00-10:15：昨天做了什么 / 今天做什么 / 卡在哪。
- **每周五 16:00 可运行 demo**：不许 PPT，必须跑起来。让延期在第 2 周暴露，不是第 11 周。

- **风险升级**：阻塞 1 工作日 → PM 升级；3 工作日 → 重新排期。
- ▲**W1 起冻结需求清单**：W1 之后新增需求一律进二期 backlog，不进本期排期。

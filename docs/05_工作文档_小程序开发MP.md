## 一、技术基线（修正）

| 项 | 选择 |
|---|---|
| 框架 | 原生微信小程序（不引跨端） |
| UI 库 | **@vant/weapp**（`miniprogram_npm` 已有构建产物，60+ 组件） |
| 换肤方式 | **`app.wxss` 覆盖 `--van-*` 变量** + 逐页重构布局；**不重写 wxss** |
| 状态 | `globalData` + 页面级 `setData`（**不引 mobx**，6 个页面用不上） |
| 请求 | `wx.request` Promise 封装：带 token、统一错误、**300ms 去重** |
| 图标 | iconfont 一次性导入 |
| 图片 | 后端返回缩略图 URL（`?w=400`），不拉原图 |

> **为什么不能"重写 wxss"**：Vant 组件样式封装在组件内部，页面级 `.cell { }` 打不进去。只能 ① 覆盖 `--van-cell-font-size` 这类变量；② 少量用 `externalClasses` 或 `:deep()`；③ 尺寸/圆角类属性只能传 prop。搞错这一点，工期从 4 天变 10 天。

### 1.1 现有页面（实测 6 个，不是 13 个）

```
pages/index/index          首页（含 tabBar）
pages/index/search         搜索
pages/index/houseInfo      房源详情
pages/userInfo/myInfo      我的
pages/userInfo/collection  收藏
pages/logs/logs            日志（可删）
```

**基数修正的影响**：6 个页面全量换肤是可行的（约 14 人日含新增页），v2 按"13 页"估算是虚高，但把省下的时间给了新增页，总量不变。

## 三、AI 选房页的流式方案（v2.1 修正，这块最容易翻车）

v2 只写了"流式推荐理由"。真实成本：

| 项 | 说明 |
|---|---|
| `enableChunked` | 需基础库 **2.20.2+**，低版本要降级 |
| 不是 EventSource | 拿到的是分块 `ArrayBuffer`，要自己 `TextDecoder` + 按 `\n\n` 切事件 |
| **半包问题** | 一个汉字被切在两个 chunk 之间会乱码 → 必须**先拼 buffer 再解码**，不能逐块 decode |
| Nginx | 必须 `proxy_buffering off; proxy_read_timeout 300s;`，否则流被缓冲成一次性返回 |
| 真机差异 | iOS / Android 的分块行为不同，必须真机验证 |

**v2.1 决策：默认走"非流式 + 打字机"，SSE 作为增强。**

```
方案 A（默认，W8 第一天做）：POST 一次拿完整文案 → 前端 30ms/字渲染
  优点：零协议风险、零兼容问题、零 Nginx 配置；用户感知与真流式无差别（本来就要等 3-8s）
方案 B（增强，有余量再做）：enableChunked 真流式
  前提：A 已上线；有 1 天时间做半包处理 + 真机验证
```

**红线：不允许为了"流式"把 W8 拖成两周。** 老板看的是"文字一个个出来"，不是 TCP 分包。

## 四、设计 tokens（单一来源）

- `design/tokens.json` 由 MP 在 W2 维护，脚本生成两份：`web/src/styles/tokens.css` 与 `wechat/app.wxss`。
- 小程序端变量以 `--van-` 前缀覆盖 Vant，自有变量用 `--app-` 前缀。

## 五、交付形态（v2.1 修正）

| 形态 | 合法域名限制 | 本期 |
|---|---|---|
| 开发者工具模拟器 | 否 | 开发期 |
| **真机预览二维码** | **否**（继承"不校验合法域名"设置） | ⚠️ **仅现场用**，官方约 25 分钟失效，不能当交付物 |
| 体验版 | **是**（需备案域名 + HTTPS + 白名单） | ⚠️ 备案通过后才有 |
| 正式版 | 是 + 房产类目 | ❌ 个人主体做不到 |

> v2 写"体验版二维码分发"是错的（体验版需合法域名），v2.1 改成"预览二维码"也不成立（**25 分钟失效，扫完即废**）。
> **v2.2 定稿：交付物是"三件套"**——3 分钟演示录屏 + 一键启动包（Web 侧 compose + README）+ 10 分钟演示脚本；二维码只在现场演示时扫，不承诺可分发。

**图片域名的坑（W1 必须验证一次）**：小程序 `<image src>` 同样受合法域名校验。若图片走后端域名，**预览模式下图片会裂**。方案：图片走本地静态相对路径 / 或 W1 实测后改 CDN。演示前一天必须验证，否则现场全是灰块。

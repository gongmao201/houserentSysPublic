## 四、关键设计（v2.1 补齐）

### 4.1 租约状态机（P0，W5 前必须上）

```sql
ALTER TABLE hrent_house_renting
  ADD COLUMN status TINYINT NOT NULL DEFAULT 0 COMMENT '0生效中 1已到期 2已退租 3已解约',
  ADD COLUMN actual_end_date DATE DEFAULT NULL COMMENT '实际退租日＝评价窗口起点',
  ADD COLUMN end_date DATE DEFAULT NULL COMMENT '合同到期日（由 end_time 迁移）';

-- 迁移：字符串日期转 DATE，转换失败的行写日志表人工处理，不静默吞
UPDATE hrent_house_renting
SET end_date = STR_TO_DATE(end_time, '%Y-%m-%d')
WHERE end_time REGEXP '^[0-9]{4}-[0-9]{2}-[0-9]{2}';
```

接口 `POST /api/v2/lease/{id}/terminate`：房东或租客任一方可确认退租 → `status=2`、`actual_end_date=CURDATE()`，写 `repair_log` 同款流水表 `lease_log`。
**评价提交的前置校验**：`status=2 AND NOW() <= DATE_ADD(actual_end_date, INTERVAL 30 DAY)`，否则 400。
**没有这个状态机，"仅租约结束后 30 天内可评"永远不触发，评分模块等于没做。**

### 4.2 金额迁移（P0）

```sql
-- 老字段只读保留；新增分字段（单位：分）
ALTER TABLE hrent_house_resource
  ADD COLUMN money_fen BIGINT DEFAULT NULL,
  ADD COLUMN deposit_fen BIGINT DEFAULT NULL;
UPDATE hrent_house_resource
  SET money_fen = ROUND(money * 100), deposit_fen = ROUND(deposit * 100);

ALTER TABLE hrent_house_renting ADD COLUMN money_fen BIGINT DEFAULT NULL;
UPDATE hrent_house_renting SET money_fen = ROUND(money * 100);
```

对账（必须脚本化，一条命令出报告）：
```
老库 SELECT SUM(money)          vs  新库 SELECT SUM(money_fen)/100     必须相等
老库 COUNT(*)                   vs  新库 COUNT(money_fen)              必须相等
抽样 100 行：ABS(ROUND(money*100) - money_fen) = 0
```

### 4.3 密码迁移（P0，W10）

不能直接覆盖（全员登录失败）。策略：**双哈希兼容读 + 登录时静默升级**。

```
登录：先按 MD5(password) 比对老字段 → 命中则用 BCrypt 重写 password 并置 pwd_algo='bcrypt'
     → 已是 bcrypt 则走 BCrypt.matches()
新增字段：sys_user.pwd_algo VARCHAR(16) DEFAULT 'md5'
```

### 4.4 评分冷启动

```
展示分 = (C × m + Σs) / (C + n)     C=5, m=4.0
最终分 = official ? official×0.4 + 展示分×0.6 : 展示分×1.0
official 为 NULL 时禁止用 0 参与加权（这是 v1 的死穴）
n < 3 → 返回 tag="NEW"，前端不显示低分
```

### 4.5 AI 三级自动降级（v3，缺一不可）

```yaml
ai:
  mode: auto              # auto（默认）| local | deepseek | rule
  local:                  # 第 1 级：本机 Ollama（经花生壳）
    endpoint: https://xxx.vicp.fun
    timeout-ms: 3000
    model: qwen2.5:3b-instruct-q4
  deepseek:               # 第 2 级：DeepSeek API（OpenAI 兼容）
    endpoint: https://api.deepseek.com/v1/chat/completions
    api-key: ${DEEPSEEK_API_KEY}
    timeout-ms: 8000
    model: deepseek-chat
  rule:                   # 第 3 级：纯规则（永远开）
    enabled: true
```

| 场景 | 行为 |
|---|---|
| `ai.mode=auto` | 依次尝试 local → deepseek → rule，任意一级成功即返回 |
| `ai.mode=local` | 强制走本机 Ollama（演示本地部署能力） |
| `ai.mode=deepseek` | 强制走 DeepSeek API（日常可靠模式） |
| `ai.mode=rule` | 纯规则 + 模板文案（<300ms，零外部依赖） |
| 规则抽取命中 ≥3 字段 | 不调任何模型，直接检索（<50ms） |
| local 超时 3s / 5xx | 自动切 deepseek |
| deepseek 超时 8s / 余额不足 / 5xx | 自动切 rule |
| LLM 返回非 JSON | 降级关键词直搜，记 warn 日志 |
| **三级全挂** | 仍返回规则结果 + 模板文案，HTTP 200，**绝不 500** |

> **关键认知**：花生壳 vicp.fun 域名不需要备案——这条链路是云托管服务器→花生壳→本机的服务器到服务器调用，不经过小程序 request 合法域名校验。
> **DeepSeek 成本**：约 6 元/百万 tokens，课程演示调用量几乎为 0。

### 4.6 幂等与并发

| 场景 | 做法 |
|---|---|
| 报修接单 | `UPDATE ... WHERE id=? AND version=?`，影响行数 0 → 409 |
| 评分提交 | 唯一索引 `(reviewer_id, target_type, target_id, lease_id)` |
| 账单确认 | 状态前置校验 + `version`；重复确认返回 200 但不重复累加 `paid_fen` |
| 账单生成定时任务 | `(renting_id, period)` 唯一索引，重复跑幂等 |

### 4.7 越权清单（每个接口都要过）

| 资源 | 规则 |
|---|---|
| 房源 | 房东只能 CRUD `landlord_id = 当前用户`；管理员例外 |
| 工单 | 租客只看 `tenant_id=自己`；房东只看 `house.landlord_id=自己` |
| 账单 | 租客只看 `tenant_id=自己`；房东只确认自己房子的 |
| 评价 | 只能评自己的租约；不能评自己发布的房源 |

### 4.8 12 个 XML mapper 复查（W3，体力活）

Boot 2.7 + MyBatis 3.5 对 `test` 表达式的类型推断更严格：`test="x != null and x != ''"` 在 `x` 为 Integer 时会抛异常。逐个改为 `x != null`，并对 `LIKE` 参数显式加 `CONCAT('%', #{q}, '%')`（防 `${}` 注入）。
**红线：全项目禁止 `${}` 拼接用户输入，QA 用 `' OR 1=1 --` 扫一遍。**

- 不允许引入 RediSearch / Milvus / 任何向量库（可选方案只用 MySQL + Java cosine）。

- 不允许用 `${}` 拼接 SQL 参数。

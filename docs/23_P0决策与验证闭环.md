### T-07 · `jjwt 0.9.1` 在 JDK17 缺 `javax.xml.bind`

| 维度 | 内容 |
|---|---|
| **结论** | **不升级 jjwt；`pom.xml` 加 `javax.xml.bind:jaxb-api:2.3.1` 兜底；JDK17 启动另加 `--add-opens`，且该参数不写进 `.mvn/jvm.config`** |
| 依据 | `jjwt 0.9.1` 的 `signWith` 用 `DatatypeConverter`，JDK11+ 已移除该类；升 0.11.5 需重写 `TokenUtils` 签发/验签并引入 7 天双验期，超出「不新增功能/最小改动」边界；加一个 API 依赖零业务代码改动 |
| 影响范围 | `hrent-api/pom.xml` +1 dependency；运行期 classpath 多 1 个 jar；启动文档 |
| 风险 | `jaxb-api` 未缓存，需联网下载（本轮 Maven Central 200，可下载）；`--add-opens` 只对 JDK9+ 有效，写进 `.mvn/jvm.config` 会让 JDK8 启动直接失败，故只写文档 |
| **是否阻塞后续验证** | **可能阻塞** `mvn clean package`（依赖下载失败时）；以第 4 章实测结果为准 |

### T-10 · mvn 安装位置不一致 + 运行时校验缺失

| 维度 | 内容 |
|---|---|
| **结论** | **引入 Maven Wrapper 固定 3.9.16（`only-script`）；不把 `.m2/repository` 提交进项目；修正两份 `.gitignore`；项目级 settings 只作可选模板、不强制覆盖** |

## 三、项目内 `.m2` 及配套内容：方案裁决

| 方案 | 做法 | 判定 |
|---|---|---|
| A · Maven Wrapper ★**采纳** | `mvnw`/`mvnw.cmd` + `.mvn/wrapper/maven-wrapper.properties` 固定 Maven 3.9.16；依赖回到各机器默认 `~/.m2/repository` | **选它**：彻底消除「mvn 在哪/哪个版本」，入库文件仅 3 个、约 20 KB，无许可证与凭据风险 |
| B · 项目内提交 `.m2/repository` | 570 个 jar 随仓库分发，离线可构建 | **否决**：体积大、第三方许可证混布、易夹带本机缓存的私有凭据，且 Git 不适合存放二进制依赖 |
| C · 只写探测脚本 + 文档 | 脚本按 PATH/常见路径找 mvn | **否决**：仍依赖机器已装 Maven 且版本不定，无法根治 |

**配套内容裁决**：
1. `.mvn/settings.xml` —— 生成**可选模板**（无 `localRepository` 绝对路径、无凭据、无镜像硬编码），**不通过 `.mvn/maven.config` 强制引用**，避免覆盖同事本机的公司镜像配置。
2. 两种运行入口：`./mvnw clean package`（用本机 settings）或 `./mvnw -s .mvn/settings.xml clean package`（用项目模板，绕开本机写死的仓库路径）。
3. **离线依赖包**：仅在「完全离线机器」场景按需生成（把本机 `~/.m2/repository` 打包为 `hrent-deps.zip`，不进 Git），本次不生成 → 标注为待确认假设 H1。
4. `.mvn/jvm.config` **不生成**（JDK8 兼容性，见 T-07）。

## 七、实测记录、缺陷与阻塞项

### 7.1 本轮修复的 4 个缺陷（均为实测触发，非推测）

| # | 缺陷 | 根因 | 修复 | 验证 |
|---|---|---|---|---|
| D1 | `/api/v2/lease/*` 全线 500 | `V2Mapper.xml` 的 `leaseCols` 引用 `g.tenant_name`，而 `hrent_house_renting` **无该列**（MySQL 1054） | 从 `leaseCols` 删除该列 | T-08 / L-02 转 PASS |
| D2 | `POST /api/v2/file/upload` 未登录返回 500 而非 600 | `@RequestParam("file")` 的绑定先于鉴权抛异常，被兜底成 500 | `required=false` + 先 `v2Context.current()` 再校验文件 | F-04 转 PASS |
| D3 | `/api/v2/lease/mine` 仍 500（修 D1 后暴露） | `V2Time.iso/day` 调用 `java.sql.Date.toInstant()`，JDK 中该方法对 `java.sql.*` **固定抛 `UnsupportedOperationException`** | 改 `Instant.ofEpochMilli(date.getTime())` | T-08 / L-02 转 PASS |
| D4 | 老接口 `/menu/getLoginMenu`、`/message/*` 500 | MySQL 8 把 `system` 列为**保留字**，`MenuDao.xml`/`MessageDao.xml` 中该列未加反引号 | 仅给 `system` 加反引号（**不改任何业务逻辑**） | OLD-7 转 PASS |

> D1–D3 是上一轮 v2 新增代码自身的缺陷，由本轮用例暴露并修复；D4 是**存量代码在 MySQL 8 下的兼容缺陷**（`MenuDao.xml`/`MessageDao.xml` 在本次之前从未改动，`git status` 可证）。

### 7.2 存量接口 2 个恒 500 的死接口（不修，登记为已知缺陷）

| 编号 | 接口 | 根因 | 影响 | 处置 |
|---|---|---|---|---|
| L-D2 | `POST /dict/get?id=x` | `DictDao.get` 的 SQL 写成 `limit #{offset}, #{limit}`，而 `BaseService.get(String id)` 传的是 **id 字符串** → `limit NULL, NULL` 语法错误 | 恒 500；`hrent-web` 与小程序**均未调用** | 不修（改 DAO 语义超出「不新增功能」边界），列入 `docs/22` 待办 |

### 7.3 存量空参健壮性缺陷（14 个，非回归）

`/houseResource/{findPage,findByRole,findViewedHousePage,findCollectionHousePage,findRentingHousePage}`、`/wechat/{findHousePage,findHouseByCondition}`、`/message/findPersonalMessage`、`/applyRent|applyView/{findPersonal*}` 等方法在空 body 下直接 `new Page<>(getPageNo(), getPageSize())` → NPE。补 `{"pageNo":1,"pageSize":5}` 后全部返回 200。属存量代码缺空值保护，**与本次改动无关**，不修。

| # | 阻塞 | 原因 | 影响 | 规避方式 |

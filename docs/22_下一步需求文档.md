### 8.2 新增待办（本次实测发现，按优先级）

| 优先级 | 事项 | 原因 | 建议做法 |
|---|---|---|---|
| **P0** | 38 个写语义老接口未回归 | 避免污染种子库，本轮全部 SKIP | 在独立测试库执行 `save/delete/upload/login` 等写接口，逐条比对返回结构与数据落库 |
| **P0** | 前端页面未做浏览器级联调 | 只做了 `npm run build` 静态构建 | 起 web 端 → 登录 → 逐个打开 v2 四个页面，验证请求/分页/错误提示 |
| **P1** | `L-D2 /dict/get` 恒 500 | `DictDao.get` 的 SQL 是 `limit #{offset},#{limit}`，与 `BaseService.get(String id)` 参数语义冲突 | 新增 `queryById` 调用或在 DAO 增加按 id 查询；改动前确认无外部依赖（已确认两端均未调用） |
| **P1** | `L-D3 /houseResource/findAll` 恒 500 | 控制器未设 `currentUser`，DAO 动态 SQL 求值 `currentUser.role==0` 抛 OGNL 异常 | 控制器补 `setCurrentUser(userUtils.getUser(request))`；或无调用则标记 `@Deprecated` |
| **P1** | 14 个存量分页接口空参 NPE | `new Page<>(getPageNo(), getPageSize())` 前未判空 | 统一在 `Page` 构造或 Controller 入口做默认值兜底（当前端必传，风险可控） |
| **P2** | 老接口「改造前快照 diff」仍缺基线 | 基线在 JDK17 无法登录（缺 jaxb），无法构造同口径对照 | 用加了 `jaxb-api` 的版本打一个「基线 jar」，再与本轮产物做同口径响应 diff |

### 8.3 环境侧两条必须写进交接文档

1. 启动命令必须带 `--server.port=8888`（部分 CI/沙箱会注入 `SERVER_PORT` 覆盖配置），同事机器无此变量时可省略。
2. `mvnw` 在受限网络/沙箱下会因探测系统信息触发告警（WMIC 拦截），**不影响构建退出码**；CI 若失败可设 `MAVEN_SKIP_RC=1`。

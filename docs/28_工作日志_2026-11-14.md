## 一、启动故障定位与修复

### 1. 复现路径

1. 用最终 jar 指向演练库 `house_rent_v8t` 起 8899，12 秒后 `/hrent/sysCommon/getBaseInfo` 返回 `000`。
2. `logs/w3app.out` 报 `FlywayValidateException: Detected failed migration to version 2 (normalize money lease role)`。

### 2. 根因

| # | 根因 | 证据 |
|---|---|---|
| 1 | `house_rent_v8t.flyway_schema_history` 残留一条 `success=0` 的 V2 记录（该库早前被当测试库，Flyway 在已有手工表结构上重跑 V2 失败） | `installed_rank=3, version=2, success=0`；库结构本身完好（手工跑到 V8 + 14 触发器） |
| 2 | `application.yml` 中 `server.port: 8888` 硬编码，`HRENT_PORT=8899` 完全不生效，新实例抢占 8888 | 启动日志 `Tomcat started on port(s): 8888` |
| 3 | 脏库同时影响单测：3 个 Spring 上下文用例 `Failed to load ApplicationContext`，全部由 Flyway validate 引起 | 首次 `mvn test` 9 用例 3 错误 |

### 3. 修复动作

| 动作 | 文件/命令 |
|---|---|
| 端口环境变量化 | `application.yml`：`server.port: ${HRENT_PORT:8888}` |
| 演练库历史修复 | `UPDATE house_rent_v8t.flyway_schema_history SET success=1 WHERE success=0`（结构已手工到 V8，等价 flyway repair） |
| 冒烟改用全新库 | 新建 `house_rent_smk`，让应用启动时 Flyway 从零跑 V1–V8，同时验证 V8 触发器可被 Flyway 解析 |
| 正式服务恢复 | `start.cmd` 拉起 8888；Flyway 自动补到 V8（14 触发器、0 失败记录），健康检查 200 |

## 三、17 条存量 INSERT 与新非空约束

| 结论 | 说明 |
|---|---|
| 非空约束不冲突 | 清空 V1 的 `INSERT IGNORE` 演示行后，17/17 全部成功；13 张老表"NOT NULL 且无默认值"的列只有主键 `id`，老语句均显式给出 |

## 四、12 个存量 XML mapper 复查

| 缺陷 | 影响 | 处理 |
|---|---|---|
| 12 个 mapper 内 `house_rent.xxx` 硬编码 | 换库、演练库无法运行 | 全部改为无 schema 表名 |
| `UserDao` 未映射 `pwd_algo` | 双哈希读不到算法标识 | resultMap 补 `pwd_algo`；insert 用 `IFNULL(#{pwdAlgo},'md5')` |
| `DictDao.get` 误用分页 SQL（`from sys_dict limit #{offset}, #{limit}`） | `/dict/get` 恒 500（`limit '0','0'` 语法错误） | 改为 `from sys_dict where id = #{id}`；全库已无 `limit #{offset}` 残留 |
| 存量行 `del_flag=1` 与 mapper 过滤 `del_flag=0` 冲突 | 老数据"查不到"，表现为 `/dict/get`、`/applyRent/get` 空指针 500 | 数据口径问题（非结构问题）；冒烟库统一归零后全部通过，待业务确认语义 |

## 五、密码双哈希

| 项 | 实测 |
|---|---|
| 存量 MD5 | `MD5("123456")=e10adc3949ba59abbe56e057f20f883e` 可校验 |
| 登录静默升级 | 首次登录后库内 `password=$2a$10$...` 且 `pwd_algo=bcrypt` |
| 修复的缺陷 | `User.pwdAlgo` 默认值 `"md5"` 导致登录成功后"更新登录时间"的第二次 update 又把 `pwd_algo` 写回 `md5`（密码 BCrypt、算法 md5，二次登录必失败）→ 字段默认值改为 `null` |
| 测试 | `PasswordDualHashTest` 迁到 JUnit5（原来 surefire 不执行）；`TokenUtilsTest` 篡改 payload 首字符（避免 Base64 填充位导致的假通过） |

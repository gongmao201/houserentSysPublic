# 08 · 评审采纳对照记录（v1 → v2）

> 本文档把架构师/QA 评审提出的每条硬伤，对应到 v2 已采纳的决策，方便回溯。
> 评审日期：2026-10-28
> 修订范围：00/01/02/03/04/05/06 全部 7 份文档已同步 v2。

---

## 一、P0 级硬伤（全部采纳）

| 评审指出 | v2 决策 | 落在哪个文档 |
|---|---|---|
| **上线路径不存在**：个人主体无房产类目、无备案、无 HTTPS 白名单、Ollama 在桌面 CPU 无公网 IP，"提审+灰度"是幻觉 | 验收口径改为"可演示系统 + 体验版二维码分发"；W1 启动 ICP 备案但不阻塞交付；内网穿透仅用于开发联调 | 00 抬头、01 W1/W12、02 W1、05 W12 |
| **Redis 7 Vector Set 是事实错误**（VADD/VSIM 是 8.0 才有） | 不引入向量库，AI 走"结构化表单 + 标签规则打分 + LLM 文案" | 00 §3.1、03 §三 W8 |
| **后端排期超载**（58 vs 51 人日） | 砍范围：Web 只重写 4 页、不新建账单三表、AI 不做向量库、契约先行 mock 并行 | 01 §三、03 全部 |
| **官方分无供给方 + 冷启动无解** | 官方分改"上架审核一次性打分"；贝叶斯平滑 C=5,m=4.0；official 为 NULL 时权重回落 | 00 §3.2、03 §4.1 |
| **存量数据契约冲突**（金额 DOUBLE 元、MD5 密码、VARCHAR 日期、单角色 INT） | W2 出迁移脚本+回滚脚本+三方对账；老字段不动，新增字段；W10 切 BCrypt | 00 §2.3、03 W2/W3/W10 |

## 二、P1 级硬伤（全部采纳）

| 评审指出 | v2 决策 |
|---|---|
| 依赖兼容矩阵没做（jjwt 0.9.1、mybatis 1.3.0、fastjson、commons-httpclient） | W1 半天 spike 清单，6 个依赖逐个清；spike 失败就留在 JDK8 |
| 缴费双轨（新建三表 vs 存量 hrent_rent） | 扩展 hrent_rent，只新增 bill_item 一张表 |
| sys_user 单角色 INT 跑不通"房东评租客" | 新增 user_role 关联表 |
| 订阅消息"自动提醒"做不到（一次性订阅） | 站内信为主，一次性订阅为辅 |
| 统一响应体是 breaking change | 老接口 /api 保留，新接口走 /api/v2 |
| QA 一人三岗会牺牲手册 | 用户手册砍到 1 册，运维手册 BE 出稿 QA 审 |

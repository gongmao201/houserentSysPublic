## 3. 月结与逾期扫描

### 3.1 月结口径

- 触发：每月 1 日 00:05（`Asia/Shanghai`），账期取当月 `YYYY-MM`。
- 候选：`del_flag=0 AND status=0`、`money_fen>0`、租约区间覆盖账期（`start_date<=账期末` 且 `end_date>=账期初`），且**同租约同账期没有账单**。
- 建账结果：`period`、`amount_fen=租约 money_fen`、`payable_time=账期-05`、`bill_status='UNPAID'`，同时写一条 `bill_item(RENT, amount_fen, remark=月租, sort=0)`。
- 返回：`period/candidates/generated/skipped/failed/failures`；重复账期（`DuplicateKeyException` 或业务 409）计入 `skipped`，其他异常计入 `failed` 并留前 5 条原因。

### 3.2 逾期扫描

| 步骤 | 行为 |
|---|---|
| 候选查询 | `bill_status IN ('UNPAID','OVERDUE')`、`payable_time < NOW()`、`overdue_notified_at IS NULL`，按应缴时间升序，`limit` 夹在 1–500 |
| 发信闸门 | `UPDATE ... SET bill_status='OVERDUE', overdue_notified_at=NOW(), version=version+1 WHERE id=? AND overdue_notified_at IS NULL AND bill_status IN (...)` |
| 并发/重复 | 只有一条 UPDATE 能 `affected=1`；其余 `affected=0` 直接跳过，不重复发信 |
| 事务 | 落状态与写 `sys_message` 同一事务；写消息失败则整体回滚，下一轮仍可重试 |
| 消息 | `message_name=BILL_OVERDUE`、`title=租金逾期提醒`、`receiver_type=0`、`receiver_id=租客 id`、`state=0` |

消息正文实测：

```text
您租住的「科华北路100号」账期 2026-11 租金 ¥2500.00 已逾期，请尽快在账单页补缴。
```

### 3.3 调度配置

```yaml
bill:
  monthly:
    enabled: ${BILL_MONTHLY_ENABLED:true}
    cron: "${BILL_MONTHLY_CRON:0 5 0 1 * ?}"
  overdue:
    enabled: ${BILL_OVERDUE_ENABLED:true}
    cron: "${BILL_OVERDUE_CRON:0 10 0 * * ?}"
    limit: ${BILL_OVERDUE_LIMIT:200}
```

`HrentApplication` 增加 `@EnableScheduling`。cron 值含空格/`*`/`?`，YAML 中必须加引号。

## 4. 费用明细追加

`POST /api/v2/bill/{id}/items`（房东或管理员）：

| 项 | 规则 |
|---|---|
| 类型 | `WATER/ELECTRIC/PROPERTY/OTHER`（`RENT` 由系统月结自动写，不允许手工追加） |
| 金额 | `amountFen > 0`，单位分 |
| 阶段 | 仅 `UNPAID/OVERDUE`；已标记/已确认账单 409 |
| 并发 | `id + version + status` 条件 UPDATE，失败 409 提示刷新重试 |
| 一致性 | 同一事务内「抬高 `amount_fen`」+「写 `bill_item`」，详情接口校验 `SUM(items)==amount_fen` |

实测：原账单 250000 分，追加 `WATER/5000/10月水费` 后，账单 `amountFen=255000`，明细为 `RENT 250000 + WATER 5000`，`version 1→2`。

### 5.3 踩坑记录（已修复）

首版站内信把 `sys_message.system` 写成 `"hrent"`，该列为 `VARCHAR(2)`，插入报：

```text
MysqlDataTruncation: Data truncation: Data too long for column 'system'
```

事务回滚后表现为 `notified=0, failed=1`，账单仍为 `UNPAID` 且 `overdue_notified_at` 为空——说明「发信失败可重试」的兜底是有效的。改为短标识 `"0"` 后重跑 `notified=1`，并补了单测断言，防止回归。
